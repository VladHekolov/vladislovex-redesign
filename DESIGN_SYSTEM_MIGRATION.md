# Миграция CSS на дизайн-систему

## Уже переведено

- `assets/css/subpages.css`
  - общая шапка `/artists/` и `/repertoire/`;
  - навигация подстраниц;
  - брендовый блок;
  - общий подвал.
- `assets/css/artist-modal.css`
  - попап артиста;
  - карточки информации;
  - галерея фотографий;
  - полноэкранный просмотр фотографии.
- переключатель темы на подстраницах использует `vh-button`.

Эти файлы больше не должны объявлять собственные семейства шрифтов, числовые значения `font-weight`, произвольные радиусы или глобальные цветовые токены.

## Где теперь менять внешний вид

- веса шрифтов, размеры контролов, радиусы, отступы и палитра:
  `assets/css/design-tokens.css`;
- заголовки, кнопки, поля, карточки и контейнеры:
  `assets/css/components.css`;
- адаптивные размеры текста:
  `assets/css/typography.css`;
- различия светлой и тёмной темы:
  `assets/css/themes.css`.

## Автоматический контроль

Команда:

```bash
node scripts/design-system-audit.mjs
```

Проверяет очищенные CSS-файлы и останавливает CI, если в них снова появляются локальные шрифты, числовая жирность, произвольные радиусы или повторное объявление глобальных дизайн-токенов.

## Следующие зоны миграции

1. Кнопки, заголовки и поля в `assets/css/repertoire.css`.
2. Основные интерактивные элементы `assets/css/style.css`.
3. Удаление временной migration map из `assets/css/components.css` после перевода HTML на общие классы.
4. Финальная очистка специальных светлых переопределений в `assets/css/themes.css`.

Сложные анимации, сетки, фоновые изображения и PDF-стили остаются локальными: они не являются частью общей компонентной системы.
